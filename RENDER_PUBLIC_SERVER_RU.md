# Serega V3 — публичный сервер на Render

## Что уже подготовлено
- `server.js` слушает `process.env.PORT` и `0.0.0.0` по умолчанию — подходит для Render Web Service.
- `render.yaml` описывает сервис `serega-v3` с командами `npm install` и `npm start`.
- Браузерная версия подключается к WebSocket на том же домене через `wss://` при HTTPS.
- Electron-клиент подключается к публичному адресу, указанному в `desktop/main.cjs`, а не к локальному серверу игры. Локальный HTTP-сервер Electron всё ещё запускается, чтобы обслуживать файлы игры.
- Кнопка приглашения формирует публичную ссылку на веб-клиент с кодом комнаты.

## 1. Развернуть сервер
1. Распакуй архив и создай приватный репозиторий GitHub, загрузив **содержимое папки `serega_work`**, а не ZIP как один файл.
2. Открой https://dashboard.render.com/ и выбери **New + → Blueprint**, затем подключи репозиторий, в котором лежит `render.yaml`. Если Blueprint недоступен, создай **New + → Web Service** и выставь: Runtime `Node`, Build Command `npm install`, Start Command `npm start`, Health Check Path `/`.
3. Для начала можно использовать Free. Первый деплой может занять несколько минут. Бесплатный сервис может засыпать после периода бездействия, поэтому первое подключение после простоя может задержаться.
4. После успешного деплоя скопируй публичный адрес вида `https://serega-v3.onrender.com` со страницы сервиса. Открой его в браузере: должна загрузиться игра. Это проверка HTTP, но ещё не полная проверка многопользовательской игры.

## 2. Привязать EXE к твоему адресу Render
1. Открой `desktop/main.cjs`.
2. Найди строку `const PUBLIC_GAME_SERVER = process.env.SEREGA_PUBLIC_SERVER || 'https://serega-v3.onrender.com';`.
3. Замени URL на **точный адрес сервиса Render**, если он отличается. Используй `https://`, не `wss://` — клиент сам преобразует схему в WebSocket.
4. В Windows установи Node.js 20 или новее. В PowerShell открой папку проекта и выполни:
   ```powershell
   npm install
   npm run check
   npm run dist:win
   ```
5. Установщик появится в `release/`. Передай друзьям именно новый EXE/установщик, а не старую сборку.

## 3. Проверить публичную игру
1. Открой новый EXE и создай комнату.
2. Убедись, что появился код комнаты.
3. Отправь другу код. Друг запускает новую сборку EXE, вводит код и нажимает «Подключиться».
4. Для проверки приглашения открой URL, который создаёт кнопка «Пригласить», в браузере на другом устройстве. Веб-клиент загружается с Render и подключается к тому же WebSocket-серверу.
5. Если не подключается, открой Render → сервис → **Logs** и проверь сообщения запуска/ошибки. Сверь, что URL в `desktop/main.cjs` точно совпадает с адресом Render.

## Важные ограничения текущей архитектуры
- Список комнат и состояние матча хранятся в памяти одного процесса. Перезапуск/деплой сервера удаляет текущие матчи.
- Не включай несколько инстансов/горизонтальное масштабирование: у каждого процесса будет собственный список комнат, и игроки могут попасть на разные экземпляры.
- Бесплатный инстанс может засыпать после простоя и просыпаться при новом подключении. Для постоянной публичной игры лучше план без сна.
- Это базовый публичный сервер, не защищённый от целенаправленного читерства/DoS. Перед крупным публичным запуском потребуются ограничения частоты сообщений, валидация всех игровых действий и мониторинг.

## Статус проверки
Проверены синтаксис JavaScript и целостность ZIP после упаковки. Сам Render-сервис здесь не создавался, деплой не запускался, а сетевой тест двух реальных клиентов не выполнялся. Поэтому адрес, подключение через интернет и работу комнат нужно проверить после твоего деплоя.
